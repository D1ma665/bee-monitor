# 🐝 Bee Monitor

Веб-приложение для распознавания частоты жужжания пчёл, оценки состояния улья по частоте и ведения истории измерений по разным ульям.

**Живая демо-версия:** https://bee-monitor-7shj.onrender.com

> ⚠️ Демо на бесплатном плане Render: сервис засыпает после 15 минут бездействия (первый запрос до 50 секунд), а история может сбрасываться при перезапуске.

## Возможности

- **Распознавание частоты** — спектральный анализ методом Уэлча, поиск основной частоты жужжания в диапазоне 40–1000 Гц
- **Рекомендации по состоянию** — по найденной частоте определяется состояние улья и даётся конкретный совет
- **Запись с микрофона** прямо из браузера или загрузка аудиофайла
- **История за 5 дней** — хранение в SQLite с автоочисткой старых записей
- **Разделение по ульям** — отдельная история и фильтрация для каждого улья
- **Статистика** — средняя, минимальная и максимальная частота по выбранному улью
- **Графики** — спектр сигнала с подсветкой диапазонов и динамика частоты во времени
- **Сортировка** — по любому столбцу истории
- **Адаптивный интерфейс** — работает на телефоне и компьютере

## Частотные диапазоны

| Частота | Состояние | Рекомендация |
|---|---|---|
| **< 70 Гц** | Низкая активность / покой | Возможно, прохладно или зимний клуб. Проверить утепление и кормовые запасы |
| **70–180 Гц** | 🔥 Вентиляция: жарко / влажно | Пчёлы охлаждают улей. Открыть леток, добавить тень, обеспечить воду |
| **180–200 Гц** | Переходный режим | Пограничное состояние. Наблюдать динамику |
| **200–400 Гц** | ✅ Стандартная работа | Норма: лёт, сбор нектара. Плановый осмотр по графику |
| **400–550 Гц** | ⚠️ Возбуждение / риск роения | Проверить маточники, свободное место, наличие матки. Готовить отводок |
| **> 550 Гц** | 🚨 Сильное возбуждение / тревога | Возможны нападение, потеря матки, вибрации. Осмотреть леток |

Дополнительно учитываются **уровень сигнала** и **температура** (если указана при замере).

> Пороги — практические ориентиры по типичному поведению медоносных пчёл, а не ветеринарное заключение.

## Быстрый старт

### Требования

- Python 3.10+
- pip

### Установка

```bash
git clone https://github.com/D1ma665/bee-monitor.git
cd bee-monitor

python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

pip install -r requirements.txt
```

### Запуск

```bash
python bee_monitor.py
```

Откройте: **http://127.0.0.1:5000**

Остановка: `Ctrl + C`.

### Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `BEES_DB_PATH` | `./bees.db` | Путь к файлу базы SQLite |
| `PORT` | `5000` | Порт сервера |
| `HOST` | `127.0.0.1` | Адрес прослушивания |

Пример:

```bash
PORT=8080 HOST=0.0.0.0 python bee_monitor.py
```

## Использование

### 1. Сделать измерение

**Способ А — запись с микрофона:**

1. Введите название улья, например `Улей 1`
2. (Необязательно) укажите температуру воздуха у улья
3. Нажмите **● Записать с микрофона** и разрешите доступ
4. Записывайте 5–10 секунд, держа устройство в 5–15 см от летка
5. Нажмите **■ Стоп** — результат появится через пару секунд

**Способ Б — загрузить файл:**

1. Введите название улья
2. Выберите аудиофайл — анализ начнётся автоматически

### 2. Прочитать результат

- **Основная частота** — главный показатель в герцах
- **Уверенность** — насколько чётко выражен пик (> 40–50 % — надёжно)
- **Уровень сигнала** — громкость записи в дБ
- **Состояние** — категория по таблице диапазонов
- **Рекомендация** — конкретные действия
- **Спектр** — график с подсвеченным пиком и цветными зонами

### 3. Работать с историей

- Фильтр **«Все ульи»** → выбрать конкретный улей
- Фильтр периода: за сутки / 2 дня / 5 дней
- Клик по заголовку столбца — сортировка
- Наведение на строку — полная рекомендация
- **✕** — удалить запись

### Поддерживаемые форматы

**Без ffmpeg:** WAV, FLAC, OGG, AIFF
**С ffmpeg:** MP3, M4A/AAC, WEBM/OPUS, MP4

> Для записи из браузера формата webm нужен ffmpeg, но пакет `imageio-ffmpeg` из `requirements.txt` уже включает его — отдельная установка не требуется.

**Ограничения:** минимальная длина записи — 0,3 с; максимальный размер загрузки — 20 МБ; для анализа используется не более 60 с аудио.

## Хранение данных

- База: файл `bees.db` (SQLite) в папке проекта
- Записи старше **5 дней** удаляются автоматически
- Таблица `measurements`:

| Поле | Тип | Описание |
|---|---|---|
| `id` | INTEGER | Первичный ключ |
| `hive` | TEXT | Название улья |
| `ts` | TEXT | Время замера (ISO 8601) |
| `peak_hz` | REAL | Найденная частота, Гц |
| `confidence` | REAL | Уверенность, 0–1 |
| `rms_db` | REAL | Уровень сигнала, дБ |
| `temp_c` | REAL | Температура, °C (может быть NULL) |
| `state` | TEXT | Состояние улья |
| `advice` | TEXT | Рекомендация |

Резервная копия:

```bash
cp bees.db bees_backup.db
```

Просмотр вручную:

```bash
sqlite3 bees.db "SELECT hive, ts, peak_hz, state FROM measurements ORDER BY ts DESC LIMIT 10;"
```

## API

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/` | Веб-интерфейс |
| `GET` | `/health` | Статус сервера, путь к БД, наличие ffmpeg |
| `POST` | `/api/analyze` | Анализ аудио (`multipart/form-data`: `audio`, `hive`, `temp_c`, `save`) |
| `GET` | `/api/history?hive=all&days=5` | История измерений и список ульев |
| `GET` | `/api/stats?hive=all` | Статистика: количество, средняя, мин/макс |
| `POST` | `/api/delete/<id>` | Удалить измерение |

Пример анализа:

```bash
curl -X POST http://127.0.0.1:5000/api/analyze \
  -F "audio=@sample.wav" \
  -F "hive=Улей 1" \
  -F "temp_c=28"
```

Пример ответа:

```json
{
  "id": 12,
  "hive": "Улей 1",
  "peak_hz": 312.5,
  "confidence": 0.63,
  "rms_db": -28.4,
  "temp_c": 28.0,
  "state": "Стандартная работа",
  "advice": "Обычный полетный шум, сбор нектара...",
  "saved": true
}
```

## Деплой на Render

Проект содержит `render.yaml` — деплой через Blueprint в один клик.

1. Запушьте репозиторий на GitHub
2. На [dashboard.render.com](https://dashboard.render.com) → **New → Blueprint**
3. Выберите репозиторий, нажмите **Connect → Deploy**
4. Готово через 2–5 минут

### Планы

| План | История | Засыпание | Стоимость |
|---|---|---|---|
| **Free** | Сбрасывается при перезапуске | Через 15 мин | $0 |
| **Starter + Disk** | Сохраняется постоянно | Нет | $7/мес |

Для постоянного хранения на Starter используйте в `render.yaml`:

```yaml
    plan: starter
    envVars:
      - key: BEES_DB_PATH
        value: /var/data/bees.db
    disk:
      name: bees-data
      mountPath: /var/data
      sizeGB: 1
```

### Запуск через gunicorn (production)

```bash
gunicorn bee_monitor:app --bind 0.0.0.0:$PORT --timeout 120 --workers 1
```

## Советы по замерам

| Правило | Зачем |
|---|---|
| Микрофон в 5–15 см от летка | Дальше — шум, ближе — перегрузка |
| Записывать 5–10 секунд | Короткая запись даёт нестабильный спектр |
| Мерить в одно и то же время суток | Для честного сравнения динамики |
| Делать 2–3 замера подряд | Одиночный замер может быть случайным |
| Не мерить при ветре, дожде, шумной технике | Помехи искажают частоту |

**План на первые дни:**

1. День 1 — по 3–5 замеров на каждом улье: определить «норму» именно ваших пчёл
2. Дни 2–5 — по 2 замера в день (утро/вечер) на каждый улей
3. Следить за графиком динамики: резкий скачок частоты — сигнал к осмотру

## Частые проблемы

| Проблема | Решение |
|---|---|
| `ModuleNotFoundError: flask` | `pip install -r requirements.txt` |
| «Нет доступа к микрофону» | Разрешить микрофон в настройках браузера; нужен `localhost` или HTTPS |
| «Не найден ffmpeg» | `pip install imageio-ffmpeg` |
| Сайт не открывается | Проверить, запущен ли сервер (`python bee_monitor.py`) |
| Порт 5000 занят | `PORT=5001 python bee_monitor.py` |
| Низкая уверенность (< 20 %) | Микрофон далеко или много шума — повторить ближе к летку |
| Частота > 1000 Гц | Посторонний звук (голос, музыка, техника) — перезаписать в тишине |
| Сервис на Render «спит» | Free-план: первый запрос до 50 с. Пинговать `/health` через UptimeRobot |
